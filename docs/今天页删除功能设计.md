# 「今天要处理」页事项删除功能 · 设计文档（终稿）

> 状态：已评审通过（对抗性评审 PASS，8 条细化意见已吸收）
> 需求原文：各种事项在今天要处理界面应该提供一个删除功能

## 一、背景与目标

今天页「临近截止」列表的行操作只有状态切换与编辑，删除必须绕道大作业/活动列表页。目标：今天页每行提供删除入口，交互与全应用删除惯例完全一致——**一次确认、永久删除、附件级联**。

## 二、代码事实（评审已逐条核实）

- 行模板在 `renderToday()`（src/renderer.js:284）：`.row-actions` = statusButton（`data-action="status"`）+ 编辑图标按钮（`data-action="edit"`）；`.deadline-row` 本体无可点交互，「打开详情」只存在于周条 → 当天待办弹窗路径，与行操作无冲突
- 全局点击委托（src/renderer.js:999-1007）：document 级 `[data-action][data-id]` → `handleItemAction()`；其中 **delete 分支已完整存在**（892-897 行）：确认弹窗 → `api.items.remove(id)` → toast「事项已删除」→ `refreshItems()` 全量重渲染（导航计数、周条、指标、搜索态一并刷新）
- 大作业 / 活动 / 逾期三个列表页已有同款删除按钮（trash 图标，`data-action="delete"`）
- 主进程 `items:delete`：附件文件逐个删除 + 外键级联清 attachments/notification_log + `notifyWidgets()`（小组件角标自动归零）
- 布局：`.deadline-row` 为 `grid: 42px / minmax(0,1fr) / auto`，行标题/副标题均有省略号；操作区加一个 35px 按钮由中列吸收，最小窗口 920px（侧栏收窄后今天面板约 500px）下中列仍余约 230px；`:has(.badge.warning)` 的 3px 左边框与 3px 左内边距和默认 6px 内边距等宽，净宽变化为零；今天列表不出现 danger 态（逾期项被过滤）

## 三、方案（改动最小化）

1. **仅改一行模板**：`.row-actions` 在编辑按钮后追加删除按钮，标记与列表页逐字一致：
   ```html
   <button class="icon-button" data-action="delete" data-id="${item.id}" title="删除"
     aria-label="删除“${escapeHtml(item.title)}”"><span data-icon="trash"></span></button>
   ```
2. **零新逻辑**：确认弹窗、删除、刷新、小组件同步、导航计数全部复用既有链路
3. **零新样式**：复用 `.icon-button`（今天页 35px，与同排编辑键等大；列表页 `.table-actions` 内被覆写为 31px 属两处容器口径差异，非本改动引入）
4. **顺序**：状态 → 编辑 → 删除（与列表页「编辑 → 删除」的相对顺序一致）；常驻可见，不做悬停显示、不加红色危险配色（与列表页一致）

## 四、交互细节

- 确认弹窗复用现有：标题「删除这个事项？」，正文「“{标题}”及其全部附件将被永久删除。」，确认键「删除」
- 关闭方式（全应用现状）：ESC、遮罩点击、回车均视为**取消**——弹窗初始焦点在「取消」键上，回车命中即取消（安全方向）；确认需点击（或 Tab 切到删除键后回车）。本功能不改弹窗行为
- 删空后 `emptyState` 自动接管：有其他事项时显示「暂无到期事项」，一条删光时显示「从第一条截止日期开始」+ 新增引导按钮
- 删除失败（主进程异常）：`execute()` 统一错误 toast，行保留
- 确认删除后焦点不回归删除按钮（DOM 已重建，还焦目标 detach）——与列表页删除现状完全一致，非本改动引入的缺陷
- 删除触发的重渲染不会重放入场交错动画（`animateTodayRows` 仅首次渲染为真）

## 五、范围外（明确不做）

- 「查看当天待办」弹窗、事项详情弹窗增加删除入口（经核实两处现均无删除入口；如需要另立需求）
