# 「截止线」· 需求文档（v1.16 · Windows 桌面版）

> 项目名称：**截止线**（Deadline Desk）
> 创建日期：2026-08-13
> 更新日期：2026-11-08（v1.16：助手 AI 配置新增接口协议，支持 OpenAI 兼容与 Anthropic Messages API；v1.15：新增「助手」页，自然语言录入、先预览再确认；AI 配置与 Key 治理）
> 状态：v1.16 已实现
> 运行平台：**Windows**
> 存储方案：**本地 SQLite + 本地附件目录**（不走云端）
> 实际技术方案：**Electron + SQLite 格式本地数据库**

---

## 一、项目概述

一个**本地 Windows 桌面工作台**，安装后可通过桌面快捷方式启动，用于：

1. **记录课程大作业**——必须完成，有硬性截止日期，分个人 / 团队，有中间状态
2. **记录参加的活动**——可选的、想完成的事，有截止日期，用于统计完成情况

核心价值：**不用再反复登录各种网站查截止日期**，打开工作台一眼看清「哪些快到期、哪些已逾期」。

**名称由来**：「截止线」= deadline 的中文意象，点题「截止日期」这个核心痛点。

---

## 二、目标用户与使用场景

- **用户**：学生
- **使用频率**：每次打开电脑都会瞄一眼，重点看「有没有快截止的大作业」
- **主设备**：Windows 电脑
- **数据归属**：全部存在**用户自己电脑的本地应用数据目录**中，不依赖平台；核心功能不需要联网，仅「助手」页调用用户自行配置的在线模型时需要网络

---

## 三、核心痛点

| 痛点          | 现状          | 目标                   |
| ----------- | ----------- | -------------------- |
| 查截止日期麻烦     | 反复登录多个网站逐个看 | 打开工作台一眼看清            |
| 忘了 / 拖到最后一刻 | 没有集中的截止提醒   | 「今天要处理」置顶区自动提醒       |
| 大作业状态混乱     | 不知道做到哪一步了   | 状态流转：未开始 → 进行中 → 已完成 |

## 四、功能模块设计

### 模块 1：「今天要处理」置顶区（页面最顶部，非独立 Tab）

**自动列出以下条目：**
- ✅ **今天到期**
- ✅ **7 天内快到期**

**范围**：大作业 + 活动都纳入。

> 往日已逾期的事项不放在"临近截止"列表中，也不再出现在大作业/活动列表和「今天要处理」页，统一进入独立的「逾期」页；逾期项仍计入统计。当天已过截止时刻但未完成的事项同样视为逾期，立即移入「逾期」页。

**交互规则：**
- 逾期事项持续保留在业务列表中，不修改原始截止日期
- 无未来 7 天待处理项时显示「暂无到期事项」的清爽提示
- “未来 7 天”日期栏中有未完成事项的日期显示为红色；点击日期可查看当天待办
- 点击当天待办中的事项可查看详情，包括类型、截止日期、状态、要求说明和附件；点击附件可打开本地文件；详情内的「当前状态」字段可直接下拉修改，底部提供编辑入口修改其余内容
- 「今天要处理」每行提供删除入口（与列表页一致）：一次确认后永久删除事项及其全部附件，导航计数与桌面小组件角标自动同步；删空后显示空状态引导
- 对未完成且已逾期、今天到期或 7 天内到期的事项发送 Windows 系统通知；同一事项同一日期不重复骚扰；今天 / 明天到期的通知文案带具体时刻（如「今天 14:30 到期」），后台每小时检查一次
- 应用运行时检查通知；关闭主窗口后驻留系统托盘并继续检查；从托盘彻底退出后不再发送通知
- 不支持开机自动启动，用户需要手动启动应用后才会开始检查通知

### 模块 2：大作业管理（核心模块）

**字段：**

| 字段   | 说明              | 必填       |
| ---- | --------------- | -------- |
| 课程名称 | 如「数据库课设」        | 是        |
| 作业要求 | 多行文本描述          | 否        |
| 截止时间 | YYYY-MM-DD HH:MM（分钟精度；23:59 视为「当天截止」，界面不额外展示时刻） | 是        |
| 状态   | 未开始 / 进行中 / 已完成 | 是（默认未开始） |
| 类型   | 个人 / 团队         | 是（默认个人）  |
| 附件图片 | 作业要求截图，原图直接存储（本地附件目录） | 否        |
| 附件文档 | 作业要求文档，PDF / Word / PPT 原文件（本地附件目录） | 否        |

**状态流转（已确认）：**
```
未开始 → 进行中 → 已完成
```
> 注：原「进行中」「快完成」已合并为「进行中」，不做更细区分。

**已确认规则：**
- 团队作业**只标「团队」标签，不记录队友 / 分工**
- 大作业**不按课程分类**，以「课程名称」字段承载课程信息
- 按截止时间排序（越近越靠前）；支持按状态筛选，筛选「全部」时已完成自动沉底
- 过点即逾期：超过截止时刻且未完成的大作业自动进入独立的「逾期」页（v1.7），不在大作业列表中显示；逾期页支持标记完成、编辑、删除，操作后事项自动移出

**交互：**
- 新增 / 编辑 / 删除大作业
- 状态一键切换

### 模块 3：活动记录

**字段：**

| 字段   | 说明            | 必填       |
| ---- | ------------- | -------- |
| 活动名称 | 如「校辩论赛」       | 是        |
| 截止时间 | 活动举办 / 报名截止时间（精确到分钟） | 是        |
| 状态   | 未完成 / 已完成     | 是（默认未完成） |

**已确认规则：**
- **只记录「参加了」的活动**；如果记录了但最后没参加，**直接删除**即可
- 不需要「想去 / 已报名 / 放弃」等复杂状态
- **活动需要截止日期提醒**：进「今天要处理」区，**超过截止日期进入独立的「逾期」页**（和大作业一致，v1.7），不在活动列表中显示

**统计需求（已确认）：**
- 想看到自己**完成了多少活动**
- 设计为：参加总数、已完成数、完成率

### 模块 5：日记（v1.8 新增）

**定位**：轻量的每日记录，用于沉淀当天的进展和想法；第一期与截止事项互相独立，不做联动。

**已确认规则：**
- 一天最多一篇日记，可以不写；以日期为唯一键，同一天的内容反复编辑覆盖
- 纯文本，单篇最多 10000 字
- 输入后约 0.5 秒自动保存到本地，无手动保存按钮；清空全部内容时自动删除该天的日记
- 删除单篇日记需一次确认

**界面交互：**
- 侧边栏新增「日记」页，该页不显示搜索框
- 左侧月历：可切换上 / 下月，有日记的日期带圆点标记，支持一键回到今天
- 右侧编辑区：显示当前日期和星期，底部展示保存状态、字数和删除按钮
- 切换日期、离开页面、输入框失焦、关闭窗口前都会先保存未写入的内容
- 日记不参与其他页面的每分钟全量重渲染，仅在进入日记页时加载

**数据：**
- 「清空全部数据」同时删除全部日记；备份 / 恢复包含日记数据（随整个数据库文件）

### 模块 6：日常任务（v1.9 拟新增，待评审）

**定位**：记录每天都要做的例行任务（如背单词、锻炼、早睡），做了就打卡。与截止事项不同，日常任务**没有截止日期、不进逾期页**，只做「当天打卡 + 连续天数」的轻量记录。

**任务字段：**

| 字段   | 说明          | 必填 |
| ---- | ----------- | -- |
| 任务名称 | 如「背 20 个单词」 | 是  |
| 备注   | 一句话补充说明     | 否  |

**打卡规则：**
- 每个任务每天最多打卡一次，以「任务 + 日期」为唯一键
- 打卡按钮是开关式：点一下 = 打卡（写入当天打卡记录），再点一下 = 取消（删除当天记录）；当天内可反复切换，以当天最后一次操作为准
- 允许补卡：最近 7 天的打卡点阵可直接点击，补打或取消某一天的卡；超过 7 天的历史不可修改
- **连续天数**：截至今天的连续打卡天数；如果今天还没打卡，先按截至昨天计算，今天结束仍未打卡则断签、重新计数
- **累计天数**：该任务历史打卡总天数

**界面交互（拟）：**
- 侧边栏新增「日常」页，放在「日记」下方（导航顺序：今天 / 日记 / 日常 / 大作业 / 活动 / 逾期 / 统计）
- 页顶展示今天日期、今日打卡进度（如「已打卡 2 / 4」）和进度条
- 任务列表每行：圆形打卡按钮、任务名、「连续 N 天」标记、最近 7 天打卡点阵（实心点 = 已打卡）
- 支持新增 / 编辑 / 删除 / 归档任务；删除需一次确认，删除后任务连同全部打卡记录一起移除；归档后任务不再出现在任何列表和统计中，但打卡历史保留，可在「已归档」区恢复或彻底删除
- 列表为空时展示引导，如「添加第一个日常任务，比如『每天背 20 个单词』」

**与其他模块的关系（拟）：**
- 「今天」页新增「今日打卡」卡片，放在右列最上方（「本周概览」之上）：列出今天还没打卡的任务，可直接点击打卡；全部打卡完成后卡片收起为一行进度
- 桌面小组件：改为「截止提醒 / 今日打卡」双视图，页头下 tab 切换并记忆上次停留的视图；截止视图保持原样；打卡视图列出全部日常任务（未完成在前、已完成沉底弱化），点击行即打卡 / 取消打卡，行尾徽标显示连续天数；角标分别显示待办数与打卡进度；小组件高度仍不超过 300px，超出内部滚动；窗口拖动把手为页头 + tab 栏，列表滚动后仍可拖动；点击截止事项行可直接打开对应事项详情，主窗口同时切到所属的大作业 / 活动 / 逾期页；详情内可直接切换状态、编辑内容
- 统计页日常任务区块：当月打卡日历（**三种状态**：未打卡不上色只留日号 / 部分完成中青 / 全部完成深青，靠明度台阶区分、图例用文字标注，周日首与日记页月历一致）与本月打卡率（Σ当天已打卡 / Σ当天应打卡，按任务创建 / 归档日逐日计算活跃；创建日之前的补卡不计入、未来日期不进分母、取整钳制在 1–99），辅以今日完成（N / M）与累计打卡两项（含已归档任务，终身口径）；移除原「今日打卡率」指标
- 系统通知、逾期页不涉及日常任务
- 「清空全部数据」同时删除日常任务和打卡记录；备份 / 恢复包含日常任务数据（随整个数据库文件）

### 模块 7：助手（v1.15 新增）

**定位与入口**：第 8 个内容页面；入口在侧边栏底部、设置之上；不显示数量角标。本次仅新增「助手」1 个模块，不新增数据表，不改事项字段、统计口径与桌面小组件结构。

**五类操作**
- **新增**：从一段自然语言中提取大作业 / 活动候选，预览中可勾选、可逐条行内编辑；疑似重复的候选默认不勾选；缺少截止时间或状态非法的候选为「待补全」，不可写入但可从本次清单移除；截止时间已过去的候选照常生成并标记「已过期」。
- **修改**：单条修改；目标唯一时默认选中，匹配到多个目标时默认不选中；预览展示每个字段的「原值 → 新值」；不改事项大类，不改动已有附件。
- **删除**：只处理明确点名的具体事项；预览文案写明「永久删除」；清单勾选后走现有二次确认；附件级联删除。
- **清理已完成**：只清理状态为已完成、且截止时间落在指定范围（上个月 / 本月 / 今年 / 某个具体月份 / 全部已完成）内的大作业与活动；没有范围时不执行；默认全选、可逐条取消；二次确认后逐条删除并报告删除条数。
- **查询 / 汇总**：只读，不写入任何数据；时间范围、类型、状态的筛选与计数全部由本地按现有事项数据计算，模型只负责组织文字；答复注明「按截止时间统计」；未说明状态时默认只答未完成事项。

**统一安全边界**
- 所有写入与删除先预览、再确认。
- 一次输入只处理一类意图；识别到多类时列出类别并提示拆分提交，不执行任何写入。
- 执行前按最新本地数据逐行复核；单行失败或目标已不存在时跳过并报告，其余行继续，不回滚已成功项。

**会话状态**
- 解析结果、预览清单与操作记录只在本次助手页会话内保留，离开助手页即清空。
- 输入文本在本次运行期间保留，重启应用后清空。

**发送字段与隐私**
- 发送给模型的字段限定为：当前输入、当前本地日期 / 星期 / 时刻、事项摘要（本地标识、标题、类型、截止时间、状态）；摘要最多 100 条。
- 不发送事项说明、附件文件、日记与打卡数据；设置页与助手页都展示该字段清单。

**AI 配置**
- 设置页新增「AI 配置」分组：接口地址（仅接受 http/https）、API Key、模型名；三项完整后助手页才可用；允许保存不完整配置以便分步填写。
- 已保存的 Key 只显示掩码，点「修改」后输入新 Key；保存时不发起连通性测试。
- 设置页新增「接口协议」下拉（v1.16）：取值 `openai`（OpenAI 兼容，默认）/ `anthropic`（Anthropic Messages API）；旧配置没有该键时按 `openai` 处理，行为与 v1.15 完全一致。
- 复用既有「接口地址 / API Key / 模型名」三项，不新增配置项或数据表；切换协议不清空已填字段。
- 保存、Key 掩码、配置完整性与助手页可用提示沿用既有逻辑，不按协议特例。

**按协议调用模型（v1.16）**
- `openai`：保持现状——POST 用户填写的完整接口地址，请求头带 `Authorization: Bearer <Key>`，请求体为 `model / temperature / messages`；响应取 `choices[0].message.content`（字符串或 `type=text` 数组），`finish_reason=length` 视为失败。
- `anthropic`：POST 用户填写的完整地址，不自动拼接路径；请求头为 `content-type: application/json`、`x-api-key: <Key>`、`anthropic-version: 2023-06-01`；请求体包含 `model`、`max_tokens`（固定 4096）、`temperature: 0`、`system`（系统提示词）以及仅含 user 消息的 `messages`；响应拼接 `content` 数组中 `type=text` 的文本，`stop_reason=max_tokens` 视为失败，空文本视为 `empty_response`。
- 行为一致性：错误映射、60 秒超时、网络失败提示、失败不写库、输入不丢失、可重试等语义保持不变；查询类指令的两次模型调用都使用当前协议。

**Key 治理**
- API Key 只保存在本机 `settings` 表，沿用现有存储方式，不额外加密。
- 导出备份与 manifest 都不包含 Key；接口地址、模型名与接口协议随备份保存。
- 恢复备份时忽略备份中的 Key，并回填本机恢复前的 Key；接口协议、接口地址与模型名随备份恢复；本机原本没有 Key 则恢复后 AI 配置为未完成。
- 「清空全部数据」不清空 `settings`，AI 配置（含 Key）在清空后保留。

**明确不做**：不处理日常任务与日记；不做周报 / 复盘 / 总结生成；不做助手历史与多轮记忆；不做回收站 / 软删除 / 归档；不做本地规则兜底解析、流式输出、tool use、多轮对话、图片 / 语音输入；不按接口地址自动识别协议；不提供多套并行配置（v1.16 修订：原「多厂商协议」一项已不再成立）。

## 五、附件方案（本地目录版，已确定）

附件保存于应用数据目录，与 SQLite 数据库分开管理；数据库记录附件元数据和相对路径。附件不上传任何外部平台，点击附件即可打开或下载到本地。

| 附件类型 | 做法 | 限制 |
|----------|------|------|
| 图片（作业要求截图） | 直接保存原图，无需压缩 | 每条最多 9 张 |
| 文档（作业要求文档，PDF / Word / PPT） | 直接保存原文件，点击即可打开或下载 | 单文件建议不超过 50MB |

> 说明：本地文件大小受硬盘空间和文件系统影响。保存失败时需要向用户明确提示，不得静默丢失附件。

## 六、数据存储、备份与恢复方案（已确定）

- **存储**：使用 SQLite 保存事项和附件元数据；附件文件保存于应用数据目录。关闭软件、重启电脑和正常升级不应导致数据丢失
- **应用数据目录**：使用 Windows 用户应用数据目录，不依赖 HTML 文件位置，不需要联网
- **备份**：设置中支持手动导出备份；一个备份文件包含 SQLite 数据和全部附件（v1.15：AI 配置中的 API Key 不进入备份，接口地址与模型名随备份保存；v1.16：接口协议也随备份保存，API Key 仍不进入备份）
- **备份命名**：每次备份生成带日期和时间的新文件，例如 `截止线备份_2026-08-14_2100.zip`，不覆盖旧备份
- **恢复**：选择备份文件后显示确认提示；确认后用备份内容覆盖当前数据，恢复数据库和全部附件（v1.15：忽略备份中的 API Key，恢复后用本机恢复前的 Key 回填；本机原本没有 Key 则恢复后 AI 配置为未完成；v1.16：接口协议、接口地址与模型名随备份恢复）
- **数据清空**：需要二次确认弹窗；清空后无法通过软件撤销，只能从备份恢复
- **示例数据**：首次安装或首次打开为**空白状态**，列表为空时显示引导提示（如「点击 + 添加你的第一条大作业」）

> 说明：本地离线数据可能因硬盘故障、系统重装、误删应用数据、清理软件或软件异常而丢失。备份文件需要用户自行保存到可靠位置。
