# 桌面小组件点击事项 → 打开对应事项详情 · 改造文档

> 状态：已实现（v1.13 + v1.14，2026-11-01；`widget-probe` 与 `smoke-test` 通过）
> 需求原文：「我在小组件点击对应事件，现在只会跳转到主界面，我现在想让他跳转到对应事件的界面」
> 关联文档：`docs/需求文档.md`（已同步升版至 v1.14）

## 一、需求澄清

### 1.1 已确认结论

| 项目 | 确认结果 |
| --- | --- |
| 点击对象 | 小组件「截止提醒」视图中的事项行（大作业 / 活动，含逾期项）；「今日打卡」行仍是点击即打卡，不变 |
| 目标界面 | 主窗口中的**事项详情弹窗**（`#itemDetailModal`），不新建独立详情页 |
| 背后页面 | 同时把主窗口切到该事项所属的列表页：大作业 / 活动 / 逾期 |
| 小组件状态 | 跳转后保持显示，位置、置顶状态、当前 tab 均不变 |
| 详情关闭后 | 停留在所属列表页；该列表已清空搜索、重置筛选，该事项不被搜索/筛选排除（长列表允许用户自行滚动） |
| 已删除 / 已完成 | 小组件数据源已排除已完成事项，删除 / 改状态会立即推送刷新；不设计「已完成」「已删除」专属落地页，仅保留一条竞态兜底提示 |

### 1.2 非目标（明确不做）

- 不新建独立的事项详情页、编辑页，也不在小组件内弹出详情
- 不做列表滚动定位、高亮闪烁、行内展开
- 不改「今日打卡」行的点击行为，也不改打卡空态「去主应用添加」的现有行为
- 不自动隐藏 / 关闭小组件
- 不改数据库结构、小组件快照字段（`id` 已存在于快照与行 `data-id` 中）
- 不改造详情弹窗的主体字段与布局（v1.13 仅隐藏「返回当天待办」键；v1.14 追加底部状态 / 编辑操作，主体仍为只读展示）

## 二、现状与差距（代码事实）

1. 小组件行已携带事项 ID，但点击时被丢弃：`src/widget.js:31-35` 的 `rowHtml()` 输出 `data-id="${item.id}"`；`src/widget.js:106-108` 只调用 `api.widget.openMain()`。
2. 桥接层只有「打开主窗口」：`preload.js:41` 暴露 `widget.openMain`，`main.js:419` 的 `widget:open-main` 直接执行 `showMainWindow()`。
3. 主窗口没有任何「打开某事项」的接收通道：`showMainWindow()`（`main.js:345-349`）只做 `show()` + `focus()`，渲染层停留在用户上次浏览的页面。
4. 详情弹窗已完整存在，可直接复用：`src/index.html:314-319` 定义 `#itemDetailModal`；`src/renderer.js:351-366` 的 `openItemDetail(item)` 读取 `state.items` 中的完整对象（含 `attachments`）渲染。
5. 详情弹窗当前只从「当天待办」弹窗进入（`src/renderer.js:1028-1031`），且返回键 `#detailBackButton` 固定表示「返回当天待办」（`src/renderer.js:1021`、`368-376`）。从小组件进入时必须处理这个来源语义。
6. 页面归属规则已在渲染层实现：逾期项只出现在「逾期」页（`src/renderer.js:416`），大作业 / 活动列表都过滤逾期项（`src/renderer.js:379`、`398`）；因此跳转页不能只按 `kind` 判断。
7. 列表可见性受顶栏搜索与页内状态筛选影响：`state.search`（`src/renderer.js:1037`）、`state.assignmentFilter` / `state.activityFilter`（`1065-1086`）。若不清空，详情关闭后可能看不到该事项。
8. 小组件数据口径：`buildWidgetSnapshot()`（`main.js:314-324`）只取 `status != 'completed'` 且 `days <= 7` 的事项（**包含逾期**）；新增、改状态、删除都会调用 `notifyWidgets()`（`main.js:480`、`492`、`501`、`513`）。

## 三、改造方案

### 3.1 总体流程

```
小组件点击事项行
  → api.widget.openItem(id)                 [widget.js]
  → widget:open-item(id)                    [main.js，校验来源窗口与 id]
  → showMainWindow()（必要时 restore）      [main.js]
  → items:open-request(id)                  [main.js → 主窗口 webContents]
  → openItemById(id)                        [renderer.js]
      重新拉取事项 → 找到事项 → 清空搜索 / 重置该页筛选
      → switchPage(所属页) → 打开详情弹窗（来源标记 widget）
  → 小组件保持原样
```

### 3.2 IPC 与 preload 约定

| 方向 | 通道 | 参数 | 返回 | 说明 |
| --- | --- | --- | --- | --- |
| 小组件 → 主进程 | `widget:open-item`（invoke） | `id: number` | `true / false` | 仅接受小组件窗口调用；非法 id 返回 `false` |
| 主进程 → 主窗口渲染层 | `items:open-request`（send） | `id: number` | 无 | 只在主窗口 webContents 上发送 |

`preload.js` 新增两个只读桥接：

```js
widget: {
  // 既有 openMain 保留，供打卡空态「去主应用添加」使用
  openItem: id => ipcRenderer.invoke('widget:open-item', id)
},
items: {
  // 既有 items 方法保留
  onOpenRequest: callback => ipcRenderer.on('items:open-request', (_event, id) => callback(id))
}
```

主窗口就绪标志与待投递 ID 在 `createWindow()` 内、`loadFile()` 之前挂载一次：

```js
let mainReady = false;
let pendingOpenItemId = null;

function createWindow() {
  // ...既有 BrowserWindow 创建逻辑
  mainReady = false;
  // 主窗口当前只创建一次；若未来支持重建，丢弃旧窗口遗留的待投递请求
  pendingOpenItemId = null;
  // 页面重载期间也视为未就绪，避免投递到尚未注册监听的渲染层
  mainWindow.webContents.on('did-start-loading', () => { mainReady = false; });
  mainWindow.webContents.on('did-finish-load', () => {
    mainReady = true;
    if (pendingOpenItemId != null && mainWindow && !mainWindow.isDestroyed()) {
      mainWindow.webContents.send('items:open-request', pendingOpenItemId);
      pendingOpenItemId = null;
    }
  });
  // 加载失败时不重试，也不把旧请求留到下一次重载
  mainWindow.webContents.on('did-fail-load', () => { pendingOpenItemId = null; });
  // ...既有 mainWindow.loadFile() 等逻辑
}
```

主进程处理（与 `widget:resize`、`widget:set-pinned` 同款来源校验）：

```js
ipcMain.handle('widget:open-item', (event, id) => {
  const win = BrowserWindow.fromWebContents(event.sender);
  if (!win || win.isDestroyed() || win !== widgetWindow) return false;
  const itemId = Number(id);
  if (!Number.isSafeInteger(itemId) || itemId <= 0) return false;
  showMainWindow();
  if (mainReady && mainWindow && !mainWindow.isDestroyed()) {
    mainWindow.webContents.send('items:open-request', itemId);
  } else {
    // 应用启动极短窗口内主窗口尚未加载完成：只保留最后一次请求
    pendingOpenItemId = itemId;
  }
  return true;
});
```

补充：
- `showMainWindow()` 增加 `if (mainWindow.isMinimized()) mainWindow.restore();`，保证主窗口最小化时跳转也能把界面带到前台（对托盘打开同样有益）。
- 投递目标固定为主窗口，不能回发给小组件，避免小组件收到无法处理的通道。
- `mainReady` 由 `did-finish-load` 置真；连续点击时 `pendingOpenItemId` 只留最后一次，渲染层再用 `openItemRequestSeq` 兜底，不需要额外队列。

### 3.3 小组件侧

仅改点击分支，把已有 ID 传出去：

```js
views.deadlines.addEventListener('click', event => {
  const row = event.target.closest('.todo-row');
  if (row) api.widget.openItem(Number(row.dataset.id)).catch(() => {});
});
```

不需要改 `widget.html` / `widget.css`，窗口尺寸、tab、置顶、拖动逻辑均不受影响。

### 3.4 主窗口接收与页面路由

在 `bindEvents()` 注册（与现有 `api.habits.onChanged` 同处）：

```js
api.items.onOpenRequest(openItemById);
```

`openItemById` 负责数据新鲜度、页面归属与上下文复位：

```js
let openItemRequestSeq = 0;

async function openItemById(id) {
  // 连续点击多行时以最后一次请求为准；
  // 直接拉取而不是复用 refreshItems()：后者失败时只 toast，会留下旧 state.items
  const seq = ++openItemRequestSeq;
  const items = await execute(() => api.items.list());
  if (seq !== openItemRequestSeq || !items) return;

  state.items = items;
  // 拉取成功后再清搜索，避免失败时出现“输入框已空、列表仍是旧筛选结果”
  state.search = '';
  $('#searchInput').value = '';

  const item = items.find(entry => entry.id === id);
  if (!item) {
    // 仅用于快照与点击之间的竞态兜底（删除 / 改状态已在小组件侧触发推送）
    showToast('事项已不存在', true);
    renderAll();
    return;
  }

  const page = routePageForItem(item);
  resetPageFilter(page);                // 目标页筛选重置为「全部」并同步分段按钮
  switchPage(page);                     // 离开日记页时触发 flushDiarySave（异步，不阻塞切页）
  renderAll();
  openItemDetail(item, { origin: 'widget', opener: $('.nav-item.active') });
}

function routePageForItem(item) {
  if (isOverdue(item)) return 'overdue';
  return item.kind === 'assignment' ? 'assignments' : 'activities';
}
```

`resetPageFilter(page)` 行为：`assignments` → `state.assignmentFilter = 'all'`；`activities` → `state.activityFilter = 'all'`；同步对应 `.segmented` 按钮的 `active` 与 `aria-pressed`；其他页面不做处理。实现时可直接复用 `bindEvents` 内已有的按钮同步写法，不要求为此新增通用组件。

页面归属规则：

| 事项状态 | 落点页面 |
| --- | --- |
| 未完成且已逾期 | 逾期 |
| 大作业且未逾期 | 大作业 |
| 活动且未逾期 | 活动 |
| 已完成（仅竞态可能出现） | 按其 kind 落到大作业 / 活动，详情展示「已完成」 |
| 已删除（仅竞态可能出现） | 不猜测页面，保持原页面并 toast 提示 |

注：小组件的相对天数按日期口径计算（当天已过截止时刻仍可能显示「今天」），落点按 `isOverdue()` 的时间口径判定；该观感差异在边界表中明确接受，本次不改快照。

### 3.5 详情弹窗来源与弹窗叠加

`openItemDetail` 增加可选来源参数，默认值兼容当天待办入口；不再引入 `state.detailOrigin`（来源只在打开时决定返回键可见性，关闭路径无需读取）：

```js
function openItemDetail(item, { origin = 'day', opener = null } = {}) {
  // ...既有详情渲染逻辑不变
  const detailWasTop = modalStack[modalStack.length - 1]?.backdrop === $('#itemDetailModal');

  // confirmModal 在 DOM 中晚于 itemDetailModal，不先收起会压在详情上方；
  // 按现有“取消”语义关闭，不新增确认流程
  if (origin === 'widget' && state.confirmResolver) resolveConfirmation(false);

  $('#dayItemsModal').classList.remove('open');
  $('#dayItemsModal').setAttribute('aria-hidden', 'true'); // 补：与 closeDayItems() 状态一致
  $('#itemDetailModal').classList.add('open');
  $('#itemDetailModal').setAttribute('aria-hidden', 'false');
  closeModalLayer($('#dayItemsModal'));

  $('#detailBackButton').classList.toggle('hidden', origin !== 'day'); // 复用 .hidden
  openModalLayer($('#itemDetailModal'), opener);

  // 详情原本就是栈顶时，重渲染后主动把焦点放回第一个可聚焦元素；
  // 否则不抢焦点，由 openModalLayer 的既有逻辑处理首次打开
  if (detailWasTop) {
    const first = focusableIn($('#itemDetailModal'))[0];
    if (first) setTimeout(() => first.focus(), 0);
  }
}
```

`closeItemDetail(true)` 的返回当天待办分支必须与上面的 `aria-hidden="true"` 成对：

```js
function closeItemDetail(returnToDay = false) {
  $('#itemDetailModal').classList.remove('open');
  $('#itemDetailModal').setAttribute('aria-hidden', 'true');
  closeModalLayer($('#itemDetailModal'));
  if (returnToDay) {
    $('#dayItemsModal').classList.add('open');
    $('#dayItemsModal').setAttribute('aria-hidden', 'false'); // 与 openItemDetail 的 true 成对
    openModalLayer($('#dayItemsModal'));
  }
}
```

- `origin === 'day'`：与现状完全一致，返回键显示「返回当天待办」；`closeItemDetail(true)` 重新打开当天待办弹窗，并同步 `aria-hidden="false"`。
- `origin === 'widget'`：返回键隐藏；关闭键、遮罩、ESC 关闭详情后露出所属列表页（若下方还有此前打开的编辑 / 日常弹窗，则回到该弹窗）。
- 详情原本已打开且位于栈顶时，重渲染后补一次聚焦，避免焦点落在被替换的附件按钮或已隐藏的返回键上；详情被其他弹窗压住时不抢焦点。
- 主窗口此前若开着编辑表单或日常任务弹窗，不强制关闭：详情作为后打开的弹窗覆盖其上，关闭详情后回到原弹窗，编辑内容不丢失。确认弹窗是例外，按上面的方式先取消。
- 从小组件进入时仍保留现有对 `#dayItemsModal` 的关闭行为：若此前停留在「当天待办」弹窗，先关闭它，避免详情下方残留无关弹窗。

`openModalLayer` 增加可选 `opener`，但必须保留现有 `document.activeElement` 回退，否则当天待办路径的焦点归还会回归：

```js
function openModalLayer(backdrop, opener = null) {
  if (!backdrop) return;
  const existing = modalStack.find(layer => layer.backdrop === backdrop);
  if (existing) {
    // 详情已打开时再次从小组件进入：用新的显式 opener 覆盖旧值；
    // 未传 opener 时保持原值，不影响当天待办路径
    if (opener && document.contains(opener) && !backdrop.contains(opener)) existing.opener = opener;
    return;
  }
  // 显式 opener 优先；未传时沿用既有 activeElement（当天待办路径依赖）
  const active = opener && document.contains(opener) ? opener : document.activeElement;
  modalStack.push({ backdrop, opener: active && !backdrop.contains(active) ? active : null });
  const first = focusableIn(backdrop)[0];
  if (first) setTimeout(() => first.focus(), 0);
}
```

当详情已经打开、用户又从小组件点击另一事项时，`existing.opener` 会被本次导航按钮覆盖；若调用方不传 `opener`，则保留原值，不改变当天待办路径。

ESC 判定改为只看 `modalStack` 栈顶。现有逻辑无条件检查 `#itemModal` 是否打开且脏，若详情叠在编辑表单之上，按 ESC 会弹出「放弃未保存的修改？」而不是关闭详情：

```js
if (event.key === 'Escape') {
  if (!modalStack.length) return;
  event.preventDefault();
  const top = modalStack[modalStack.length - 1]?.backdrop;
  if (state.confirmResolver) { resolveConfirmation(false); return; }
  if (top?.id === 'itemModal' && isItemFormDirty()) {
    askConfirmation('放弃未保存的修改？', '关闭后本次填写的内容不会保存。', '放弃修改')
      .then(confirmed => { if (confirmed) closeItemModal(); });
    return;
  }
  closeTopModal();
  return;
}
```

这是对既有 ESC 逻辑的最小修正：只有编辑表单本身位于栈顶时才询问是否放弃；详情在栈顶时按一次 ESC 只关闭详情。

## 四、边界与异常

| 场景 | 行为 |
| --- | --- |
| 主窗口隐藏（关闭按钮只是 `hide()`） | `showMainWindow()` 正常 show + focus，并投递打开请求 |
| 主窗口最小化 | `restore()` 后 show + focus，再投递 |
| 主窗口启动中（`mainReady === false`） | 只保留最后一次 `pendingOpenItemId`，`did-finish-load` 后补发；加载失败清空，不重试 |
| 连续快速点击不同事项 | 以最后一次请求为准（`openItemRequestSeq` 丢弃较早请求的后续处理） |
| 点击瞬间事项被删除 | 重新拉取后找不到，toast「事项已不存在」，主窗口正常显示，不崩溃 |
| 点击瞬间事项被标记完成 | 事项仍在，按其类型落到大作业 / 活动，详情显示已完成状态 |
| 主窗口此前打开编辑 / 确认弹窗 | 确认弹窗先按取消语义收起；编辑弹窗保留在详情下方，ESC 只按栈顶处理，关闭详情后回到编辑，不丢未保存内容 |
| 用户此前在日记页 | `switchPage` 的既有逻辑会触发 `flushDiarySave()`（异步，不阻塞切页），不会丢草稿 |
| 小组件已置顶 | 保持置顶；主窗口仍会 show + focus，不改变置顶设置 |
| 小组件显示「今天」但当天已过截止时刻 | 小组件按日期口径显示，落点按 `isOverdue()` 时间口径判定，会进入「逾期」页；本次接受该差异，不改快照 |
| 小组件整表重建与点击重叠 | `replaceView()` 可能使 pointerdown 所在按钮在 click 前脱离 DOM，极小概率丢失本次跳转；本次接受，不为此改渲染策略 |
| 主窗口加载失败（`did-fail-load`） | 清空 pending，不重试；主窗口可能停留在错误页或上次页面；小组件侧 `.catch(() => {})` 静默；不承诺 renderer toast |
| 主窗口已加载后的 IPC 异常 | 小组件侧 `.catch(() => {})` 静默；主窗口侧 `execute()` 统一 toast，现有风格不变 |

竞态兜底说明：小组件快照不包含已完成事项，删除与状态变更也会即时推送刷新，因此「已删除 / 已完成」不是常规路径；上述处理只覆盖点击与推送之间的极短窗口，不额外建设空状态或引导页。

## 五、验收标准

1. 小组件点击未来 7 天内的大作业：主窗口显示，左侧导航落在「大作业」，并自动打开该事项详情；标题、类型、截止时间、状态、要求说明、附件与数据一致。
2. 小组件点击活动：落在「活动」页并打开同一事项详情。
3. 小组件点击逾期事项（小组件包含逾期项）：落在「逾期」页并打开详情。
4. 小组件保持可见，窗口位置、置顶状态、当前 tab 均未变化。
5. 关闭详情后，主窗口停在对应列表页；搜索框为空、该页筛选为「全部」，该事项不被搜索/筛选排除并出现在列表中（列表较长时允许用户自行滚动）。
6. 从「当天待办」进入详情的原有路径不变：返回键仍显示「返回当天待办」并能返回。
7. 主窗口隐藏或最小化时，点击小组件能把主窗口带到前台。
8. 无数据库迁移、无新增模块，现有探针无回归。

## 七、验证方案

### 7.1 自动探针（扩展 `scripts/widget-probe.js`）

在现有「新增事项 → 小组件出现 1 行」之后、原有删除之前插入大作业跳转段：

1. 先在主窗口切到「大作业」页，把筛选设为「未开始」并在搜索框输入一个不匹配的关键词，用于验证跳转时的上下文复位；再用 `electronApp.evaluate` 隐藏主窗口，用连续两次一致采样等待小组件的 `widget:resize` 高度上报落定，再记录 `widgetBounds()`。
2. 点击小组件 `.todo-row`，用 `waitForFunction` 同时等待弹窗打开与标题匹配（异步链：IPC → 拉取 → 切页 → 弹窗，禁止即时断言）。
3. 断言：`#detailTitle` 等于「探针测试事项」；`#detailBackButton` 含 `hidden`；`.nav-item[data-page="assignments"]` 含 `active`；`#searchInput` 为空、`#assignmentFilters [data-filter="all"]` 的 `aria-pressed === 'true'`；主窗口 `isVisible === true`；小组件仍存在且 bounds 未变。
4. 关闭详情，等待 `aria-hidden === 'true'`，再切回「今天」页并等待页面可见，之后继续原有删除流程。
5. 原有删除断言与角标归零断言之后，再追加逾期 / 活动夹具；不要在大作业夹具仍在小组件时插入额外事项，否则会破坏既有「角标 === 1 / === 0」断言。

// 在 widgetBounds() 旁新增：连续两次采样一致才认为高度已落定
async function waitStableWidgetBounds(app) {
  let previous = null;
  let stable = 0;
  for (let i = 0; i < 20 && stable < 2; i++) {
    const current = await widgetBounds(app);
    stable = previous && current
      && previous.x === current.x && previous.y === current.y
      && previous.width === current.width && previous.height === current.height
      ? stable + 1 : 0;
    previous = current;
    await new Promise(resolve => setTimeout(resolve, 100));
  }
  if (!previous) return null; // 交给调用方的 assert 报“未找到小组件窗口”
  if (stable < 2) throw new Error('小组件窗口在 2 秒内未稳定，无法做 bounds 断言');
  return previous;
}

// 预置会挡住事项的上下文，验证跳转时会复位
await mainPage.locator('.nav-item[data-page="assignments"]').click();
await mainPage.locator('#assignmentFilters [data-filter="not_started"]').click();
await mainPage.locator('#searchInput').fill('不存在的关键词');

await electronApp.evaluate(({ BrowserWindow }) => {
  BrowserWindow.getAllWindows().find(win => win.getTitle() === '截止线')?.hide();
});
const boundsBefore = await waitStableWidgetBounds(electronApp);
assert(boundsBefore, '跳转前未找到小组件窗口');

await widgetPage.locator('#widgetRows .todo-row').first().click();
await mainPage.waitForFunction(() => {
  const modal = document.querySelector('#itemDetailModal');
  return modal?.getAttribute('aria-hidden') === 'false'
    && document.querySelector('#detailTitle')?.textContent.trim() === '探针测试事项';
}, null, { timeout: 15000, polling: 100 });

// 只比较本次点击前后的 bounds；后续新增夹具会改变小组件高度，不能复用这个基准
const boundsAfter = await waitStableWidgetBounds(electronApp);
assert(boundsAfter, '跳转后未找到小组件窗口');
assert(Math.abs(boundsAfter.x - boundsBefore.x) <= 2
  && Math.abs(boundsAfter.y - boundsBefore.y) <= 2
  && Math.abs(boundsAfter.width - boundsBefore.width) <= 2
  && Math.abs(boundsAfter.height - boundsBefore.height) <= 2,
  `小组件 bounds 在跳转后发生变化：${JSON.stringify({ boundsBefore, boundsAfter })}`);

// 断言段落见上；关闭后：
await mainPage.locator('#itemDetailModal .detail-close').click();
await mainPage.waitForFunction(

async function assertWidgetJump(widgetPage, mainPage, title, pageId) {
  await hideMain();
  await widgetPage.locator('#widgetRows .todo-row', { hasText: title }).click();

      && document.querySelector('#detailTitle')?.textContent.trim() === title
      && document.querySelector(`.nav-item[data-page="${pageId}"]`)?.classList.contains('active');

## 九、风险与取舍

- **投递时序**：应用启动瞬间主窗口可能尚未加载完成，用 `mainReady` + `pendingOpenItemId` 补投递；加载失败清空待投递，不做重试队列。
- **上下文复位**：清空搜索、重置筛选会让用户丢失原列表浏览状态，但这是「跳转后能看到对应事项」的必要代价；只重置目标页，另一页筛选保持。
- **详情来源上下文**：origin / opener 存入 `state.detailItemId`、`state.detailOrigin`、`state.detailOpener`，供编辑 / 状态刷新后复用；`closeItemDetail` 清空，当天待办路径默认值不变。
- **已知小概率限制**：小组件整表重建与点击重叠时可能丢失本次跳转；小组件按日期显示「今天」、落点按具体时刻判定逾期，可能产生观感差异。两项均在本稿明确接受，不在本次扩大实现。
- **改动面**：主进程 1 个 IPC + 启动就绪补投递 + 桥接 2 个方法 + 渲染层入口函数 + 详情来源上下文 + ESC 栈顶修正 + 详情底部操作区；无数据库、无新模块。
